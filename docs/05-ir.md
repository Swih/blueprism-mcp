# IR : ce que l'agent remplit, ce que le générateur transforme

L'IR (représentation intermédiaire) est le **seul** format que le LLM produit. Il est validé par zod, puis transformé de façon déterministe en XML Blue Prism 7.5.1. Il décrit **l'intention** (quels éléments, quelles actions) ; le générateur se charge de **la plomberie** (GUID, liens, pages standard, arguments du catalogue, mise en page).

## Objet (`ObjectSpec`)

```ts
type ObjectSpec = {
  name: string;                 // "RPA Challenge - Form" (convention <Application> - <Écran>)
  description: string;          // narrative de l'objet
  runMode: "Foreground" | "Background" | "Exclusive";
  application: ApplicationSpec;
  elements: ElementSpec[];
  actions: ActionSpec[];        // une action = une page publiée
};

type ApplicationSpec =
  | { kind: "BrowserLaunch"; name: string; browserPath: string; url: string; extraArgs?: string[] }
  | { kind: "BrowserAttach"; name: string; /* paramètres selon le catalogue apptypes */ };

type ElementSpec = {
  key: string;                  // identifiant stable dans l'IR (sert aux GUID et aux références)
  name: string;                 // "Form - First Name Field"
  type: string;                 // type AMI : WebTextEdit, WebButton, WebElement…
  match: Record<string, string | number | boolean>;    // identifiants en correspondance (inuse)
  captured?: Record<string, string | number | boolean>; // valeurs observées, non utilisées
  rationale?: string;           // pourquoi ces attributs (repris dans le rapport)
};

type ActionSpec = {
  name: string;                 // "Set Field First Name", "Click Button - Start"
  description: string;          // narrative de la page
  inputs: ParamSpec[];
  outputs: ParamSpec[];
  steps: StepSpec[];
};

type ParamSpec = { name: string; type: "text" | "number" | "flag" | "date" | "datetime" | "password"; description: string };

type StepSpec =
  | { kind: "launch" }                                              // Navigate Launch sur l'application
  | { kind: "close" }                                               // Navigate WebCloseApplication
  | { kind: "waitFor"; element: string; condition?: string;         // défaut : WebCheckExists
      timeoutSeconds: number; onTimeout: ExceptionSpec }
  | { kind: "write"; element: string; value: string }                // value : expression BP, ex. "[First Name]"
  | { kind: "read"; element: string; action: string; into: string } // action de lecture du catalogue
  | { kind: "act"; element: string; action: string; args?: Record<string, string> } // WebClick, WebSendKeys…
  | { kind: "calc"; expression: string; into: string }
  | { kind: "raise"; exception: ExceptionSpec };

type ExceptionSpec = { type: "System Exception" | "Business Exception" | string; detail: string };
```

`into` désigne un data item de la page. Le générateur crée les data items nécessaires : entrées, sorties et cibles de `read` / `calc`.

## Ce que le générateur garantit (règles de [01-spikes.md](01-spikes.md))

| # | Garantie |
|---|---|
| G1 | Racine `appdef` typée `Application` (type, basetype, datatype `unknown`, diagnose). |
| G2 | `apptypeinfo` complet selon le catalogue `apptypes` (5 paramètres pour BrowserLaunch en 7.5.1, dont `prelaunchbrowser`). |
| G3 | Chaque élément porte **tous** les identifiants du catalogue dans leur ordre ; `inuse` seulement pour `match`. |
| G4 | Chaque étape applicative porte **tous** les arguments déclarés pour son action ou sa condition. |
| G5 | L'action et la condition sont **autorisées** pour le type d'élément (catalogue), sinon erreur de génération explicite. |
| G6 | GUID = uuid v5 d'un chemin stable `objet/page/typeÉtape/nomÉtape`, avec une **vérification d'unicité** qui échoue plutôt que d'écrire un doublon. |
| G7 | Page principale avec `ProcessInfo` (options de code pour un objet), pages `Initialise` et `Clean Up` présentes. |
| G8 | Paramètres des étapes `Action` avec `friendlyname`. |
| G9 | Pas de `loginhibit` par défaut. |
| G10 | `waitFor` : branche timeout, puis `WaitEnd`, puis étape `Exception` avec le type et le détail fournis. |
| G11 | Mise en page lisible : colonne principale, branches d'erreur à droite, data items regroupés. |

## Banc de test (`TestHarnessSpec`)

```ts
type TestHarnessSpec = {
  object: string;                       // nom de l'objet testé
  calls: { action: string; inputs?: Record<string, string>; expect?: Record<string, string> }[];
  cleanupAction: string;                // ex. "Terminate" : appelé en Recover avant de relancer l'exception
};
```

Le process généré appelle chaque action dans l'ordre, expose les sorties attendues comme sorties du process, et contient le bloc de sûreté Recover, Terminate, Resume, rethrow. La vérification des sorties (relecture indépendante via le listener `outputs`) est faite par `@bpdev/bridge`, pas dans le process.

## Hors périmètre de cette version

Attributs dynamiques, mode UIA et fenêtres natives, Attach, remplissage du template de process. Ils viendront par extension de l'union `StepSpec` et de `ApplicationSpec`, sans casser l'existant.
